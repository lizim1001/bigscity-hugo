# 可复制的任务提示词

把方括号占位换成自己的材料。若不清楚 slug 或路径，可以交给 AI 决定；不清楚正文和事实时，AI 不应替你编造。

## 0. 第一次打开项目（通用前置指令）

```text
请先阅读项目根目录 AGENTS.md、docs/01-项目速览.md 和 docs/02-AI内容维护指南.md。
确认你操作的是 bigscity-hugo 原版还原迁移，而不是旧 web 镜像。
只需读取目标任务相关文件，不必通读全部旧页面。
请保留原站外观和已有修改，编辑源码而非 public，做必要预览/构建验证。
不要推送、部署或修改生产服务器，除非我后续明确授权。
下面是我的任务：[粘贴任务]。
完成后告诉我修改了哪些文件、页面 URL、入口在哪里、验证结果和还需要我补什么。
```

## 1. 修改已有页面（不知道文件位置也可以）

```text
按项目维护指南，找到网站中的[页面名称/URL/独特文字]。
把[原文字]改为[新文字]，在[某段/某模块]后新增[内容]。
我提供的附件位于[本地路径]，用途是[图片/PDF/幻灯片]。
请直接修改现有正文文件，不创建重复页面，不改变 URL 或原站排版。
如果发现历史同名副本，告诉我它们的位置，本次只修改[指定地址/全部相关副本]。
请检查图片和链接，并构建验证，不部署。
```

## 2. 首页新增新闻并带详情

```text
请在首页 News 区域新增一条新闻：[真实标题、日期、短介绍]。
同时创建 Markdown 详情页，正文是[材料]，栏目归属为[news/其他]。
首页短条目链接到详情，详情带返回入口；不增加主导航，不破坏旧模块结构。
附件是[路径和用途]。如 news 已存在，沿用其实际结构，不覆盖栏目首页。
```

## 3. 新独立页面 + 可选主导航

```text
新增一个叫[联系我们]的普通 Markdown 页面，内容是[正文]。
请选择不冲突的英文 slug，并使用默认新页框架。
入口要求：[加入主导航 / 只从首页某段链接 / 暂时草稿]。
附件：[无/路径]。不要添加虚构联系方式或示例链接。
```

## 4. 新主栏目 + 多个子页面

```text
新增“[成果]”主栏目并加入顶级导航。
栏目首页介绍：[内容]。
子页面清单：
1. [成果 A：完整文字、附件、图片]
2. [成果 B：完整文字、附件、图片]
请创建 _index.md 栏目首页和各子目录 index.md，维护首页子页入口与返回链接。
列表方式：[目前手动列表 / 以后会持续增加，请实现该栏目自动列表]。
本任务[不需要下拉导航 / 需要下拉导航，见下面的展开要求]。
请避免修改现有 Publications，构建验证，不发布。
```

## 5. 在已有栏目中新增子页面

```text
在[栏目名称或 URL]下新增[标题]子页面，正文是[材料]。
请判断父栏目当前是 index 还是 _index，处理目录关系且保留父页原 URL 和外观。
新页用 Markdown，父页增加清晰入口，子页增加返回链接。
主导航不新增顶级项。[是否增加现有下拉子项]。
```

## 6. 新论文（提供这些信息就够了）

```text
使用 archetypes/publication.md 创建一篇新 Markdown 论文页，并让它出现在现有 Publications 首页。
题目：[题目]
作者：[作者顺序]
会议/期刊：[名称]
年份：[数字]
摘要：[原文]
方法/结果：[材料，可省略]
BibTeX：[真实引用]
PDF：[本地文件路径或真实外链]
方法图：[路径，可省略]
代码/项目/DOI：[真实链接，可省略]
请选择合适 slug，按约定放图片附件，删除模板占位项，不单独加主导航。
如果缺真实材料请列出并保留草稿，不编造。验证详情页和列表入口，不部署。
```

## 7. 展开/下拉导航（需要 AI 实现与测试）

```text
我希望主导航的[成果]可以展开，子项是[标题及对应页面]。
父项仍能进入成果首页；手机上能点击展开，键盘也能操作。
请遵循 02 指南 E2：先检查原站子菜单结构/CSS/JS，优先复用现有机制。
现有 nav.py 不支持下拉，不要使用不存在的参数。
请在备份后最小范围修改所有相关框架，包括 default；不要删掉其他旧子菜单。
必要时添加并显式引用独立 CSS/JS。验证首页、旧页、新 Markdown 页，以及手机/键盘交互。
如果扩展导航维护工具，请提供 help、dry-run、备份与测试，并更新文档。
```

## 8. 一类固定结构页面 + 自动列表

```text
我们以后会持续新增[项目/成果/活动]页面，固定内容是[字段和章节]。
请建立可复用 archetype；必要时补充渲染模板，并实现[栏目 URL]的自动列表。
列表排序：[年份降序/日期降序/明确顺序]；分类要求：[无/具体要求]。
保留旧站外观，不把这个规则错误套用到所有栏目。
当前 baseof 直接输出 Content，请核实模板是否真的被调用。
给出一份真实材料样例、以后新增指令、验证结果，并同步维护文档。
```

## 9. 局部强调与图片排版

```text
在[页面位置]将[短通知]适度标红/加粗，其他内容保持不变。
不要只靠颜色传达重要性，不改变全站配色。
图片[路径]希望[独立一行/居中/两栏]；保留手机版可读性，写清晰 alt。
如果添加 CSS，请确认被实际页面引用，而不是仅放到 static 中。
```

## 10. 旧 HTML 转 Markdown（不是日常小修改）

```text
请把[明确 URL]对应旧 HTML 正文转换为更易维护的 Markdown。
保持页面地址及原站外观，先评估哪些布局需要组件/模板，保留必要脚本依赖。
不要仅改扩展名，不保留两个冲突 index 文件，不丢失原作者、图片、引用和链接。
转换前后核对内容、页面标题、导航、桌面/手机排版；报告不能无损转换的部分。
```

## 11. 构建交付（不涉及服务器）

```text
请检查本次新增页面与资源、入口和 draft 状态，执行生产构建。
交付可部署 public 内容的位置，说明实际构建命令、错误/警告与验证结果。
不要使用 -D 发布草稿，不推送、不上传服务器。
```

## 12. 单独授权服务器发布

```text
我授权发布本次已确认的修改到[明确服务器和网站]。
连接方式：[已配置 SSH/其他]；源码目录：[路径]；专用 Web 根目录：[路径]；域名：[根域名]。
请先核实部署脚本参数、权限和现有部署方式，备份/保留可回滚版本。
不得删除共享目录或把 cleanDestinationDir 指向源码。
完成后检查页面、资源和旧页面是否仍可访问；给出回滚方法。
如缺服务器信息或权限，停在本地交付并告诉我缺什么。
```

## 13. 导出 / 导入项目

```text
请准备一份可以交给其他同学继续维护的 Hugo 源项目包，以及单独的部署成品包。
源包保留配置、content、layouts、data、static、archetypes 和实际依赖/维护工具，不只给 public。
排除凭证、缓存、临时测试和多余备份；不要未经允许删除原文件。
注明 Hugo 版本、预览/构建命令和部署路径约束。
```

迁入传统 HTML/WordPress 是单独迁移任务，不是把导出文件放到 content 就完成。要求 AI 先说明转换范围、原样保留范围、后端边界和验证方案。
