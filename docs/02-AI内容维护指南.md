# AI 内容维护指南（执行规范）

本文件提供给 Codex 等工具使用。用户只需描述内容、位置、附件和展示目标，AI 负责落实文件与验证。它不授予推送或生产部署权限。

## A. 任务开始：识别项目与权限

1. 确认根目录有 hugo.toml、content、data/legacy.json；读 01 文档、用户任务、相关代码。若打开的是 web 镜像，应定位 bigscity-hugo，不在原镜像中实现新增页面。
2. 检查适用 AGENTS.md、Git 状态与已有修改。目录不是 Git 仓库时说明情况，不能擅自初始化仓库。
3. 仅补问会实质改变结果的信息：真实正文/附件缺失、同名路由冲突、替换旧栏目还是新增独立栏目、明确要求的生产部署等。对普通 slug、目录组织做合理假设并说明。
4. 不编造论文作者、成果、数据、日期或链接。缺失材料使用明确的草稿占位并保持 draft:true；不能把示例发布成正式内容。
5. 路径不在当前可写工作区时请求工具权限，不能通过绕过沙箱完成写入。

## B. 决策表：创建哪些文件

| 用户任务 | 内容操作 | 入口操作 |
| --- | --- | --- |
| 改已有页面 | 定位并编辑原 html/md | 通常不新增文件，不改 URL |
| 首页加一条新闻 | 修改 content/_index.html 对应模块 | 有详情时再建详情页并加链接 |
| 新独立页面 | content/<slug>/index.md | 从指定位置链接；主导航可选 |
| 新主栏目 | content/<section>/_index.md | 顶级导航 + 首页明确子页链接 |
| 栏目子页面 | content/<section>/<slug>/index.md | 父页链接、子页返回链接 |
| 多级栏目 | content/<section>/<subsection>/_index.md 和更深的叶页 | 各层入口分别维护 |
| 新论文 | content/publications/<slug>/index.md | 当前列表自动追加，不单独加主导航 |
| 另一类批量同结构页面 | 正文 + 必要的新 archetype/渲染逻辑 | 普通栏目默认手写列表；要求自动时实现并测试 |
| 下拉/展开导航 | 正文目录按上面规则 | 不可用现有 nav.py 冒充实现；见 E |

一个目录不同时有 index.html/index.md，也不同时用 index 和 _index。已有叶页面要变成父栏目时，先备份、核对 URL 与 legacy_key，再改成 _index，验证旧地址和样式；不要直接覆盖。

## C. 修改已有 HTML 或 Markdown

### 旧 HTML

- 用标题/独特文字搜索 content；读完整目标页及其 Front Matter，不编辑 public。
- 小修改保留原标签、CSS 类、模块 ID、列结构和顺序。新增独立块不复制冲突 id。
- 保留 url、legacy_key、legacy_source，除非任务明确涉及路由/迁移。
- 改旧标题时检查正文标题及 legacy prefix 的 head title，不假定 title 元数据已同步。
- 正文与 HTML 属性正确转义；图片 alt、下载链接和移动端换行需检查。
- 页面有历史副本时列出可能重复地址，按用户范围处理，不默默扩展到全站。

### Markdown

- 修改现有 md，不创建第二个同地址页面。保留字段类型及必要元数据。
- raw HTML 可用于复杂块，但不要让整个新页又变成一份旧页拷贝。
- 不把 index.html 简单改扩展名为 md。若要求转换，先提取正文、映射样式组件、保留路由、审计脚本依赖，再替换并验收。

## D. 新页面 / 新栏目 / 新论文：标准步骤

1. 选稳定的英文小写短横线 slug，例如 urban-flow-2026；不使用空格、中文文件名、特殊符号来增加路径管理负担。
2. 确认路径、Front Matter url 以及 public 输出地址无冲突。
3. 创建普通页：`hugo new content contact/index.md`。
4. 创建栏目：`hugo new content achievements/_index.md`。
5. 创建子页：`hugo new content achievements/result-a/index.md`。
6. 创建论文：`hugo new content --kind publication publications/urban-flow-2026/index.md`。
7. 填真实元数据与正文，删除模板示例附件链接；根据任务决定 draft。
8. 放资源、写链接、补父页入口/返回链接、按需加入导航；不要给每篇论文建服务器配置。
9. 预览、构建、检查输出和资源；说明修改文件和可访问 URL。

命令只负责创建文件，不填写真实内容、不上传附件、不部署。若文件已存在，不运行创建命令强行覆盖。可以按同样结构直接创建文件。

### 元数据约定

普通页面：title、draft；date 可按实际需求填写。没有需求不要额外使用未来 publishDate。新论文：title、authors（当前是字符串）、venue、year（数字）、draft。新页不照抄 legacy_key 或 legacy_source。

当前论文首页逻辑读取元数据生成短条目；作者/会议在详情正文中仍需填写。新增文档字段如 DOI、tags，不会自动展示，必须同步模板才有作用。taxonomy/term 当前关闭，不承诺自动分类页。

### 同结构页面的模板选择

- 偶尔新增：default.md + Markdown 标题和章节即可。
- 长期固定章节：添加 `archetypes/project.md`，使用 `--kind project`；它只提供初始文字。
- 元数据统一渲染/自动列表：先读现有 baseof 和模板查找机制，再选择最小改动，例如在 baseof 中按 Section 或 type 分支，或扩展 block 并添加相应模板。不能只新建一个常规 single 模板便假定 baseof 会调用它——当前 baseof 直接输出 Content，没有常规 main block 渲染结构。
- 自动列表只作用到目标栏目，旧栏目原正文不被无意重写；分类、排序、draft 处理必须有测试。

## E. 导航：顶级入口、下拉、栏目列表不是同一件事

### E1 顶级导航（现有能力）

```powershell
python tools/nav.py add --label "成果" --url /achievements/ --dry-run
python tools/nav.py add --label "成果" --url /achievements/
```

更新所有相关 legacy shell，包括 default；脚本自动备份，追加到主菜单末尾。不会自动生成下拉、排序、当前页高亮。重复同 URL 添加会跳过，不可用 add 来重命名。

删除脚本新增项：

```powershell
python tools/nav.py remove --url /achievements/ --dry-run
python tools/nav.py remove --url /achievements/
```

只删除脚本自己带标识的条目；旧原站导航不由 remove 删除。新页入口移除也不删除正文。全量恢复 legacy 备份会撤销其后其他导航修改，恢复前检查差异。

### E2 用户要求展开导航（需实现，不是现成命令）

用户只说“展开”时确认是主导航子菜单，还是正文中的折叠列表；对使用方式、默认展开与手机行为做明确说明。

主导航子菜单执行协议：

1. 抽取 default 以及带已有子菜单的代表性 shell，定位 mainNav1；用实际 HTML 的嵌套 ul/li、类名、脚本与 CSS 判断原站机制。不假设一个 hover CSS 就够，也不复制整页。
2. 同时核对旧页不同相对路径和新页根路径。新链接采用根路径并在每个框架中唯一定位父项。
3. 自动修改时以 JSON 结构读取/写回，只改目标 prefix 中的目标菜单；先完整备份，计算全部变更再写入。不得用跨整个 JSON 的宽泛正则替换。
4. 不能删除已有其他子菜单或替换整份 default 框架。默认页和旧页都应能看到新父项及其子项。
5. 优先复用真实原站机制；若补充 CSS/JS，放 `static/assets/css/site-enhancements.css` / `static/assets/js/site-enhancements.js`，并显式接入框架或公共模板。仅放入 static 不会自动引用。
6. 父项既有栏目落地页又可展开时，使用独立的可访问按钮控制子菜单，或其他经过验证的交互；不要让点击父项无法到达栏目页。若按钮不能完全复用原结构，说明必要的局部变化。
7. 处理键盘焦点、Enter/Space 操作、aria-expanded、手机点击、长标签和多层级；不能只有鼠标 hover。
8. 至少检查首页、原有论文页、新 Markdown 页；验证同一子项不重复、关闭/展开正常、无其他导航回归。
9. 若未来经常维护，可按任务扩展 nav.py 增加父项/子项命令或集中配置。实现后必须更新本指南、CLI help 和测试，不能先在文档里写不存在的参数。

正文折叠列表不是导航：可使用经过测试的 `<details><summary>更多成果</summary>...</details>`，保持链接可访问，不为它改全站导航。

## F. 静态资源规则

新增图：`static/assets/img/<section>-<slug>-<purpose>.png`；例如 publications-urban-flow-2026-framework.png。
新增附件：`static/downloads/<slug>-paper.pdf`、`<slug>-slides.pptx`。文件扩展名使用真实格式，检查重复，不覆盖别人的资源。

链接中不写 static：

```markdown
![方法框架](/assets/img/publications-urban-flow-2026-framework.png)
[论文 PDF](/downloads/urban-flow-2026-paper.pdf)
```

大小写与磁盘一致（Linux 区分大小写）。保留许可证和来源信息；图片适当压缩但不牺牲文字可读性，不无授权重新下载远端媒体。页面包资源可与 index.md 同目录保存并用相对地址，但团队默认采用上述 static 规则避免混用。新代码不能擅自重命名大量旧 CDN 资源。

## G. 小 tips：强调、图片和内容组织

- 标红适合短期截止日期、重要通知、待确认提示，不适合整段正文和全部论文标题。优先正文粗体；禁止仅用颜色表达意义。
- 新 md 可使用 `<span style="color:#b00020;"><strong>重要：报名于实际日期截止</strong></span>`。当前 unsafe=true 支持 HTML；全站统一样式更适合独立 class，但必须确保新 CSS 已引用。
- 不要改变旧首页整个配色；按现有模块局部调整。占位提示应在草稿里明确，不用红字掩盖未经核实信息。
- 给图片写有意义 alt；附件标明 PDF/PPTX，可加大小；链接文字写“下载论文”，而不是大量“这里”。
- 论文页面至少有摘要、方法图/说明、资源、引用；没有真实代码链接就删去对应条目。
- 小提示可保留在文档，不能让内部操作说明出现在正式页面。

## H. 验证、构建和发布

```powershell
hugo version
hugo server --disableFastRender
# 需要预览草稿时
hugo server --disableFastRender -D
# 停止预览后生产构建
hugo
```

若 hugo 不在 PATH，用实际 hugo.exe 完整路径与 PowerShell `&` 调用，不假定所有同学都有同一安装路径。当前项目已用 Extended 0.166.0 验证，其他版本需验证而不是盲目降级。

验收：

- 修改范围/Git diff 正确；无同路由内容冲突，无 placeholder 正式发布。
- 新页在 public 中存在、真实标题正确、父页入口/返回链接正确。
- 每个新增本地图片/PDF 实际存在于输出中，链接大小写正确。
- 新论文在 publications 列表恰好出现一次；普通栏目入口手动维护或自动逻辑有明确实现。
- 旧页 CSS、脚本、图片和导航未被误删，桌面/手机检查；不具备视觉工具时明确未完成视觉验证。
- draft:false 正式页被构建，draft:true 草稿不会意外上线；生产不要使用 -D。
- check_fidelity 是迁移基线工具，内容有意变化会出现差异，不能当成零差异要求或链接检查器。

`hugo --cleanDestinationDir` 只在明确的专用输出目录中运行，不指向源码、共享目录或未核对的生产目录。删除页面后普通构建可能留有旧文件，要安全清理构建输出及服务器过期文件。

发布必须用户授权：上传整个 public 内容或按已核实的服务器流程发布。deploy-server.sh 会 git pull 并写默认 WEB_ROOT，不清理旧输出，不能未经核对直接执行。默认根域名部署；子目录发布需要审计旧相对链接和新根路径，不是只改 baseURL 就保证正常。

新加页面不用修改 Nginx，每页也不需要“部署文件”。构建产物含全部页面。源项目导出须带 content/layouts/data/static/archetypes/config 和实际依赖；只导出 public 不能恢复 Markdown 和模板。

## I. 完成报告与异常分支

报告新增/修改文件、页面地址、入口位置、资源、命令、验证结果、需要用户补充的材料和部署状态。

- 材料不全：做草稿或停止相应部分，列出缺失；不编造。
- 路由已存在：优先更新或提出不同 slug，禁止覆盖。
- 变更需改全站框架：解释范围并备份，做最小变更，验证代表页。
- 构建失败：定位真实错误，不关闭 HTML 安全设置或移除全部 legacy_key 来绕过。
- 外部服务不可用：报告后端/第三方边界，不承诺 Hugo 可以恢复。
- 用户只问规划：只解释，不自动发布或修改。
- 需要生产权限：交付本地结果，明确请求授权，不绕过权限。
