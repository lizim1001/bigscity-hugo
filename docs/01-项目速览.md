# 项目速览：不用读完整个仓库也能开始工作

## 1. 项目在做什么

BIGSCity 实验室主页，使用 Hugo 构建静态网站。来源是清理过的 Jimdo 网站本地镜像。迁移重点是保留原来的导航、结构、字体、颜色、模块和资源，不换主题、不重设计。

基线迁移保留 250 个正式 HTML 内容页，包括历史重复路径。后续数量可能改变。旧站的 Current Visitors、登录等残留已去除，不要重新引入。远程表单、第三方服务等后端能力不因静态迁移而恢复。

当前不是“全部正文都是 Markdown”的标准化重构：旧内容保留 HTML，新内容可以用 Markdown。Hugo 将源正文和框架组合为可部署的 HTML。实验室服务器、GitHub Pages 都可以托管，GitHub 不是必选项。

## 2. 构建关系

```text
content/ 正文 + data/legacy.json 原站外壳 + layouts/ 渲染逻辑
                              + static/ 静态资源
                                      ↓ hugo
                                  public/ 成品
```

Hugo 是构建工具，不是自带拖拽编辑器或在线后台。只需在构建机器安装，生产服务器可以只运行 Nginx/Apache。

## 3. 主要结构与查找入口

| 路径 | 作用 / 什么情况下修改 |
| --- | --- |
| `hugo.toml` | 域名和 Hugo 配置；当前允许 HTML 正文及原始 HTML 渲染 |
| `content/_index.html` | 原站首页正文、News 等信息 |
| `content/publications/_index.html` | 原论文列表正文 |
| `content/publications/<slug>/index.html` | 原有论文页 |
| `content/publications/<slug>/index.md` | 推荐的新论文页 |
| `content/<section>/_index.md` | 新栏目首页，可包含子页面 |
| `content/<section>/<slug>/index.md` | 新子页面 |
| `data/legacy.json` | 不同旧页的 prefix/suffix；导航、head、外壳、尾部等；default 用于新页 |
| `layouts/_default/baseof.html` | 正文与外壳组合；现有新论文追加列表逻辑 |
| `layouts/_default/single.html`、`list.html`、`layouts/index.html` | 当前精简模板入口；不是常规主题的完整页面代码 |
| `archetypes/default.md` | 创建普通 Markdown 页时的初始内容 |
| `archetypes/publication.md` | 创建论文 Markdown 页时的初始字段和章节 |
| `static/assets/img/` | 推荐存放新增图片 |
| `static/downloads/` | PDF、PPTX 等附件 |
| `static/image.jimcdn.com/` | 原站正文图片镜像 |
| `static/u.jimcdn.com/` | 原站实际布局 CSS、字体 CSS、头图 |
| `static/assets.jimstatic.com/`、`fonts.jimstatic.com/` | 原站公共样式、脚本、图标、字体 |
| `static/assets/css/` | 历史整理样式；不能假定这里的 CSS 已被页面引用 |
| `static/CNAME` | GitHub Pages 可选域名文件；不配置实验室服务器 DNS |
| `tools/nav.py` | 顶级导航 add/remove/dry-run；实际修改自动备份 |
| `tools/migrate_original.py` | 一次性迁移，日常不运行 |
| `tools/migration-manifest.json` | 基线页面路径与哈希记录 |
| `tools/check_fidelity.py` | 与原镜像比较，不是普通链接检查器 |
| `deploy/` | 实验室服务器脚本及 Nginx 示例，需核对实际参数 |
| `.github/workflows/` | 可选 GitHub 自动部署 |
| `public/` | 构建结果，不是编辑入口 |
| `docs/` | AI 指导和样例，不直接发布 |

其他已有栏目包括教师介绍、Students & Alumni、Seminars、Readings、Visualizations、LibCity、VecCity 等；实际文件以 `content/` 为准。

## 4. 必须知道的项目特殊行为

1. 旧页 Front Matter 的 `legacy_key` 选择对应框架。不要为了使用 Markdown 随意删除它或整个旧正文。
2. 新页不填 `legacy_key`，使用 default 原站框架。新页标题由模板显示；旧页 title 字段不保证同步改变原 head 或正文中的标题。
3. 顶级导航在 legacy 框架中；只写 `hugo.toml` 菜单配置不会生效。
4. 只有现有 `/publications/` 首页会追加 Section 为 publications 且没有 legacy_key 的新常规页面。没有自动年份分类；普通新栏目不自动列子页。
5. archetypes 是“创建时复制的初始内容”，layouts 才是“每次构建使用的渲染模板”。更改前者不会同步已有页面。
6. 原站学生目录可能还有相同论文的历史副本，改一份不等于同步所有路径。

## 5. 快速定位而不是全站通读

在项目根目录使用：

```powershell
rg --files content
rg -n "要找的标题或独特句子" content
rg -n "mainNav1" tools layouts
```

修改正文只读目标页和相关入口；导航需读 nav.py 和代表性框架；渲染变化需读 baseof。不要将巨大的 legacy.json 或所有 CDN 文件全部塞进模型上下文。

新增普通页用 `hugo new content contact/index.md`；新论文用 `hugo new content --kind publication publications/my-paper/index.md`；预览用 `hugo server --disableFastRender`；构建用 `hugo`。更完整规则见 02 文档。
